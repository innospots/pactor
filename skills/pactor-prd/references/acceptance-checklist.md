# 验收清单

验收是必经阶段。启动 dev server，用浏览器（playwright-cli / WebBridge 均可）执行，输出验收结果表。**全部通过才算完成；任何一项不通过，修复后重验该页全部项。**

**增量（已有工程）**：对 **本次变更的每个 page id** 跑下方「每页检查项」；另抽 **1～2 个未改动的核心页**（如首页、任一列表）做路由可达 + 控制台无新增 error，作为回归。

## 每页检查项

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 路由可达 | 菜单点击进入或直接访问 path，页面正常渲染，无 404 |
| 2 | 数据源 | 页面所有 http 数据源返回 200（Network 面板确认），无 401/404/500 |
| 3 | 渲染符合线框图 | 区域结构、字段、文案与线框图一致；无臆造元素，无缺失区域。布局/尺寸/间距不要求还原线框图，以模板工程同类页面为准 |
| 4 | 交互闭环 | 线框图描述的每个交互逐项操作：筛选变化触发列表刷新、按钮跳转/弹窗、表单可提交并有成功反馈 |
| 5 | 表单结构 | 所有表单（独立页/内嵌面板/弹窗抽屉/**搜索栏**）均由 `Form` 包裹（搜索栏 `layout: inline`）：字段 `name` 绑定、`rules` 校验就地报错、`submit: true` 提交；回填经 `form.setValues`；无散放字段 + setState 手写校验；表格操作列按钮统一 `Button variant: link`，「编辑」打开与「新建」相同的表单且数据预填正确 |
| 6 | 错误分支 | 校验失败有提示、错误操作有反馈（如登录错误密码 toast）、删除有确认 |
| 7 | 控制台 | 无 error/warning（hydration、key、表达式求值失败等） |
| 8 | 空态/多态 | 筛到无结果有空态；特殊状态条目（告警/停用等）按线框图展示 |

## 全站检查项（最后执行一次）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| A | 菜单完整性 | 菜单与 PRD 模块树一致，页面清单中每个页面均可达（含 hidden 的详情/编辑页经列表跳转） |
| B | 深浅色 | 切换深色模式：无白边、无死色、文字对比正常；markdown 代码块在深色下可读 |
| C | 换肤 | 每套皮肤切换一次：全站组件（含图表）随肤变化，首屏无闪烁 |
| D | 与原产品对比 | 关键页面（首页/登录/至少一个列表页 + 一个详情页）与原产品并排目检：视觉风格（令牌/皮肤/自定义 CSS）一致、交互行为一致；排版细节以模板工程为准 |
| E | 自定义 CSS 挂载 | 原产品的页面级 CSS（如登录页）确实生效——**浏览器目检**，不以文件存在为准 |

## 常见坑（历史踩坑记录）

- **dev server 不会因 yaml 改动热重载**（yaml 在服务端模块加载时读取）：改 `src/server/yaml/**` 后重启 dev server 再验
- **端口冲突**：启动前 `lsof -nP -iTCP:<port> -sTCP:LISTEN`，已有 dev server 直接复用
- **两段数据路径被当详情解析**：选项类接口用单段路径（`/api/d/project-members` 而非 `project/members`）
- **toast 消失快误判未触发**：验证错误提示时在操作后立即截图/读 DOM
