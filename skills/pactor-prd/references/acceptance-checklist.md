# 验收清单

验收是必经阶段。**静态检查、浏览器功能验收、截图目检三层全部通过，且全站检查通过，才算完成；三层互相不能替代。** 浏览器使用 playwright-cli / WebBridge 均可，所有证据来自目标项目真实 dev server。

- **新建工程**：对页面清单中的每个生成页执行三层检查和下方全站检查。
- **增量（已有工程）**：对本次每个 **add / update** page id 执行三层检查；另抽 **1～2 个未改动的核心页**（如首页、任一列表）做路由可达 + 控制台无新增 error/warning 的回归。

## 每页第一层：静态检查

按 `ui-quality.md` 第 7.1 节逐页执行并记录 S1–S8；对该页实际 YAML 运行 `npx pactor validate <实际文件路径>`。任一 S 项失败，该页即不通过。

| 编号 | 检查项 | 通过标准 |
| --- | --- | --- |
| S1 / S8 | UI 计划门禁与一致性 | `docs/prd/ui-plan.md` 有该 page id 的唯一完整行且早于本次 YAML 生成 / 修改；实际区域、布局、组件、字段、文案、交互、状态和窄屏规则逐项等于计划，差异已有 PRD 依据和书面变体理由 |
| S2 | DSL 与路由 | validate 通过；文件、page id、sitemap pages / menus 一致；hidden 详情 / 编辑有真实入口和 activeMenu |
| S3 | 布局、Field 间距与响应式 | 区域顺序和标准骨架 / 已论证变体符合计划；gap / gutter 来源合法，无新增 margin、空白文本或绝对定位补丁；Field 管理 label / labelHint / description / error；固定多列网格已按桌面 / 窄屏规则转换 |
| S4 / S5 | Form 与组件语义 | 搜索为 inline Form，提交字段有 name / rules / submit，新建与编辑共用 Form；无嵌套 Form、双 label 或手写必填动作链；逐区组件和 props 符合当前组件契约及 `ui-quality.md` 第 5 节，不用 Text / CSS 拼凑现有组件 |
| S6 / S7 | 数据、交互与状态接线 | 每个 PRD 交互都有 events / actions 闭环；查询和重置同步表单与请求状态；empty / loading / error / disabled 四项均有真实数据或事件来源、正确组件和条件表达式，不适用项在 UI 计划中有依据，不混用 empty 与 loading / error，不编造 props |

## 每页第二层：浏览器功能验收

在真实浏览器逐项操作并记录 F1–F6。功能通过不能代替静态检查或截图目检。

| 编号 | 检查项 | 通过标准 |
| --- | --- | --- |
| F1 | 路由与数据源 | 菜单点击进入和直接访问 path 均正常，无 404；Network 中页面所有 http 数据源返回 200，无 401 / 404 / 500；请求参数与 UI 计划一致 |
| F2 | 交互闭环 | 逐项操作 PRD 中的查询、重置、新建、编辑预填、提交、删除确认、跳转、弹窗 / 抽屉、重试和清空；每项都产生计划中的数据、路由或可见结果，实际操作不绕开 UI 计划 |
| F3 | 表单与错误分支 | rules 校验失败时就地提示且不发出请求；提交成功有反馈，失败保留输入并有错误提示；新建 / 编辑复用同一 Form，删除有确认，错误凭证等失败分支可观察 |
| F4 | empty / loading / error / disabled 行为 | 用真实响应或事件触发计划中适用的四项状态：初始空与筛选空可区分，loading 不闪 Empty，error 有反馈和重试，disabled 在鼠标与键盘下均不触发且解除后恢复；不适用项与 UI 计划依据一致 |
| F5 | 组件与键盘行为 | 实际操作页面存在的 Select / Combobox / TreeSelect / Cascader / DatePicker / Tabs / Table / CardList 等组件，选中值、清空、搜索、层级和行 / 卡片行为符合组件契约及计划；覆盖适用的 hover / focus、Tab 顺序、Enter / Space 和 Escape 焦点返回 |
| F6 | 控制台 | 全流程无 error/warning，包括 hydration、key、表达式求值失败和组件 props 警告；不得以页面可操作为由忽略警告 |

## 每页第三层：截图目检

按 `ui-quality.md` 第 7.2～7.3 节生成并检查真实页面证据：桌面 `1440×900`、窄屏 `390×844`，亮色 / 暗色；对 `normal` 及计划中适用的 `empty`、`loading`、`error`、`disabled` 各截取四种视口 / 主题组合，对 `hover`、`focus` 至少保留桌面亮色 / 暗色证据。文件保存为 `docs/prd/ui-evidence/<page-id>/<state>-<desktop|narrow>-<light|dark>.png`，验收结果引用实际文件；不适用状态不减少其他适用矩阵。

逐项记录 V1–V9，只写 `通过` 或 `不通过`，不能用功能通过或平均分抵消视觉失败。

| 编号 | 目检项 | 通过标准 |
| --- | --- | --- |
| V1 / V9 | UI 计划与信息层级 | 截图中的 PRD 区域顺序、标题、操作、组件、文案、状态、列数和位置与 `docs/prd/ui-plan.md` 当前行一致；没有无来源的额外区域或遗漏 |
| V2 | 布局与 Field 间距 | 同组 Field 间距相等；label、labelHint、description、error 无双份、重叠或遮挡；按钮基线符合 Form layout，error 出现后相邻字段仍可操作 |
| V3 | 桌面 / 窄屏与溢出 | 两种视口的主操作均可达，列数、换行和内部滚动符合计划；390px 无整页横向滚动、控件重叠、不可读截断或被裁浮层，表格内部滚动不带动整页 |
| V4 | 亮色 / 暗色 | 页面、Card、Input、Table、Empty、图表及 body 浮层均随主题切换；无白边、死色、文字融入背景或暗色下不可读 |
| V5 / V6 | empty / loading / error / disabled | 状态互斥且呈现与计划一致；无双空态、无 loading 闪 Empty，error 有重试；disabled 的标签和原因可读、无位置跳变，状态出现时布局不坍塌 |
| V7 / V8 | hover / focus 与组件行为 | hover 不造成位移，focus 环在亮色 / 暗色均完整可见，焦点返回正确；结合 F5 的实际操作确认组件选中、清空、搜索、层级、页签和行 / 卡片行为，不仅凭静态截图判定 |

## 全站检查项（最后执行一次）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| A | 菜单完整性 | 菜单与 PRD 模块树一致，页面清单中每个页面均可达，hidden 详情 / 编辑页经真实入口可达 |
| B | 模板占位、真实品牌与样板残留 | 新建工程从包含 `skills/` 的仓库根目录运行 `node skills/scripts/prd-template.mjs check <project> --rendered` 并通过；所有模式均检查页面、metadata、登录提示无未替换模板占位，无模板或其他项目的真实品牌、账号、皮肤残留；PRD 未要求的脚手架演示页面还须删除其在 sitemap、菜单、fixture 与 mock 中的对应内容 |
| C | 默认皮肤亮暗色 | 默认皮肤分别在亮色、暗色模式检查首页、登录、至少一个列表页和一个详情页：令牌生效，无白边、死色、遮挡或对比度异常；markdown 代码块在暗色下可读；不能替代每页截图矩阵 |
| D | 每套已注册皮肤 | **每套已注册皮肤**都切换检查一次，不预设皮肤数量：全站组件（含图表和 body 浮层）随肤变化，首屏无闪烁，刷新后选择仍生效；不能用默认皮肤结果替代其他皮肤 |
| E | 异常横向溢出 | 关键页面在 `1440×900` 和 `390×844` 检查 `document.documentElement.scrollWidth <= clientWidth`；无整页异常横向滚动、被裁主操作或浮层，表格只允许自身区域按契约横向滚动 |
| F | 原产品对比或替代目检 | 原产品存在时，关键页面与原产品并排目检，视觉风格、令牌 / 皮肤 / 自定义 CSS 和交互行为一致，排版以标准骨架为准；**原产品不存在时**，结果明确写「原产品不适用：未提供；已按 PRD + UI 计划 + 模板目检」，并依据 PRD、`docs/prd/ui-plan.md` 和同类标准骨架 / 模板逐项检查区域、布局、组件、文案、状态和交互，不得虚报「与原产品一致」或「原产品对比通过」 |
| G | 自定义 CSS 挂载（适用时） | 有原产品页面级 CSS 时，在浏览器确认其真实生效并符合主题 / 布局契约，不以文件存在为准；无原产品 CSS 时明确记为不适用 |

## 修复与重验

任一层任何一项失败，页面结论即为不通过。失败登记、计划 / 实现责任判断、根因修复和证据更新按 `ui-quality.md` 第 8 节执行，并遵守以下范围：

1. 记录 page id、S / F / V 或全站编号、四层 UI 质量分类、日志 / 截图、预期与实际结果；同一页的多个失败分别登记。
2. 实现偏离有 PRD 依据的 UI 计划时修实现；计划遗漏或误解 PRD 时先修 `docs/prd/ui-plan.md`，补齐来源和变体理由，再修实现。不得删除状态、交互或验收矩阵来换取通过。
3. **任何修复后，重新执行该页全部三层**：S1–S8、F1–F6、完整适用截图矩阵和 V1–V9；不得只重跑失败点击、单张截图或单项 validate。
4. 共享骨架、主题令牌、皮肤或公共组件变化时，所有受影响变更页都执行整页三层重验，并重跑未改页回归和受影响的全站检查。
5. 重验截图替换同名旧图，结果表记录修复内容和本轮结果；旧失败证据仅用于追踪。仍有未处理失败时不得写通过或交付。

## 常见坑（历史踩坑记录）

- **dev server 不会因 YAML 改动热重载**（YAML 在服务端模块加载时读取）：改 `src/backend/resources/yaml/**` 后重启 dev server 再验
- **端口冲突**：启动前 `lsof -nP -iTCP:<port> -sTCP:LISTEN`，已有 dev server 直接复用
- **两段数据路径被当详情解析**：选项类接口用单段路径（`/api/d/project-members` 而非 `project/members`）
- **toast 消失快误判未触发**：验证错误提示时在操作后立即截图/读 DOM
