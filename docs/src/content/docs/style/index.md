Pactor 建立一套基于 **shadcn/ui Semantic Token** 的 UI 视觉体系。它同时约束 `@pactor-app/ui` 的组件实现和业务页面的样式使用，为主题切换、组件复用与页面扩展提供一致基础。

> **传统色负责品牌表达，shadcn Token 负责 UI 秩序。**

## 整体模型

设计决策分为五层：

| 层级 | 职责 | 示例 |
| --- | --- | --- |
| Primitive | 提供未经语义化的原始颜色候选 | 群青 `#2E59A7` |
| Theme | 从颜色资产中形成具有品牌倾向的主题候选 | Qunqing Theme |
| Semantic | 将主题色映射为稳定的 UI 语义 | `primary`、`background`、`border` |
| Component | 由语义 Token 驱动组件视觉与状态 | Button、Card |
| Page | 在组件能力范围内组织业务界面 | Dashboard |

Primitive 资产与 UI 色彩方案相互独立。原始颜色仅提供候选；进入 Theme 后，颜色才开始承担品牌角色；进入 Semantic 后，颜色才获得稳定的 UI 含义。业务页面不得直接依赖 Primitive Color。

技术实现链如下：

```text
中国传统色
Primitive Color
       ↓
主题候选色
Theme Source
       ↓
shadcn Semantic Token
       ↓
Tailwind Theme Token
       ↓
shadcn Components
       ↓
业务页面
```

Tailwind Theme Token 是 Semantic Token 的实现映射，不构成独立的设计层。设计决策只能沿该链路向下落实：上层约束下层，下层不得反向定义全局规则，业务页面也不得成为公共 Token 的事实来源。

## Style 与 Theme

```text
Style ≠ Theme
```

**Style** 决定稳定的组件语言，包括字体、排版、间距、尺寸、圆角、阴影、结构、控件密度和动效。**Theme** 决定可替换的视觉配色，包括品牌色、表面色、前景色、边框色、状态色和图表色。

Theme 可以变化，但**禁止**借换肤改变组件尺寸、结构或交互行为。Style 的变化属于规范或组件版本变更，不属于主题切换。

Token 是实现机制，不等于 Theme。颜色 Token 属于 Theme；字体、圆角、间距等非颜色 Token 属于 Style。两者可以使用相同的 CSS 变量与 Tailwind CSS v4 映射机制，但必须保持职责分离。

## 设计原则

### 语义优先

组件和页面**必须**使用语义角色表达设计意图，不得把某个原始色值、具体主题或局部页面样式当作公共语义。

### 一致可复用

相同含义**应该**使用相同 Token、组件变体和交互模式。公共规则应在最接近其职责的层级实现，避免页面重复定义。

### 克制扩展

定制**必须**依次考虑：语义 Token、组件公开变体或属性、受控的 Tailwind 工具类、局部 CSS。只有现有能力无法表达且理由明确时，才可以进入下一层。

### 无障碍默认

颜色、排版、交互状态和动效**必须**把可访问性作为默认约束，而不是交付后的补充检查。

### 渐进增强

视觉增强可以改善体验，但**不得**成为内容理解或核心操作成立的唯一条件。

## 规范用语

| 用语 | 含义 |
| --- | --- |
| **必须** | 所有实现都要满足；不满足即为规范缺陷 |
| **应该** | 默认遵循；偏离时必须说明理由 |
| **可以** | 允许采用的可选方案 |
| **禁止** | 任何实现都不得采用 |

## 实现边界

- **禁止**在业务页面随意使用原始颜色、任意值或另一套全局主题变量。
- **禁止**依赖组件内部结构选择器进行跨项目覆盖；定制应使用公开 Token、变体、属性或稳定钩子。
- 局部例外**必须**限制作用域并记录原因；经过重复验证后，才可以评估是否沉淀为公共能力。
- 尚未实现的能力**必须**明确标记为提案或规划，不得与当前有效规范混写。
- 文档声明与代码实现不一致时，应视为缺陷并同步修正，不得默认任一方天然优先。

## 规范地图

- [色彩](./colors/)：定义整体 UI 色彩方案，负责 Theme Source 到 Semantic Token、Tailwind 映射和组件状态的规则；不维护 Primitive 资产全集。
- [字体](./fonts/)：定义字体家族、字重资源、加载与跨平台回退；不负责文字层级。
- [排版](./typography/)：定义文字层级、字号、行高、对齐与内容节奏；不负责字体资源管理。
- [布局](./layout/)：定义空间体系、页面结构、布局模式与响应式规则；不负责容器的视觉表面。
- [形态](./shape/)：定义圆角、边框、阴影、层级与表面关系；不负责页面空间组织。
- [动效](./motion/)：定义状态过渡、反馈动画、性能边界与减少动态效果策略；不改变组件行为语义。

## 角色责任

组件维护者负责将 Semantic Token、Tailwind 映射和公开变体落实为稳定的 shadcn/ui 组件能力。业务开发者负责通过这些公开能力组合页面，不绕过语义层建立局部视觉体系。

## 变更检查

样式规范或实现发生变化时，**必须**同步检查：

- 语义 Token 与 Tailwind CSS v4 映射；
- shadcn/ui 原语与 Pactor 组件；
- 亮色、暗色及品牌主题；
- 现有业务页面的兼容性；
- 可访问性与减少动态效果设置；
- 对应规范、指南和示例。
