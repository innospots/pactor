# Spec: asset-library-shell

## ADDED Requirements

### Requirement: 站点统一顶部导航

资产库站点 SHALL 提供统一顶部导航，包含 Logo 与四个模块入口：`文档`、`资产库`、`主题生成器`、`案例`，右侧提供搜索入口与当前构建版本显示。`文档`入口为指向现有 Pactor 文档站的外链，其地址 MUST 收敛为单一配置常量（环境变量可覆盖）。当前所在模块（资产库）的导航项 MUST 高亮。标记为「待设计」的模块（主题生成器、案例）MUST 显示状态标识，且其入口 MUST NOT 指向不存在的页面。

#### Scenario: 切换模块

- **WHEN** 用户点击顶部导航的「资产库」
- **THEN** 进入资产库默认页（样式总览），且「资产库」导航项高亮

#### Scenario: 待设计模块入口

- **WHEN** 用户查看顶部导航中的「主题生成器」或「案例」
- **THEN** 该入口显示「待设计」标识，且不会导航到 404 页面

### Requirement: 三栏响应式布局

资产库页面 SHALL 采用三栏布局：左侧导航 240px、中间内容区自适应、右侧看板 280px，顶部导航与底部信息栏通栏。中间内容区 MUST 可独立滚动。屏幕宽度不足时（<1024px）左右两栏 MUST 收起为抽屉，优先展示中间内容区。

#### Scenario: 桌面三栏展示

- **WHEN** 用户在桌面宽屏打开任一资产库页面
- **THEN** 左侧导航、中间内容、右侧看板三栏同时可见，且中间区可独立滚动

#### Scenario: 小屏抽屉

- **WHEN** 用户在宽度小于 1024px 的视口打开资产库页面
- **THEN** 左右两栏默认收起，可通过触发器以抽屉形式展开，中间内容区完整可见

### Requirement: 资产分类导航

左侧导航 SHALL 只保留两级：一级分类 Tab（固定为 `样式`、`组件`、`主题`、`模板`、`素材`）与二级子菜单，MUST NOT 出现三级菜单。切换一级分类后 MUST 替换下方二级菜单并默认打开该分类的「<分类名>总览」。当前 Tab、当前子菜单与左侧滚动位置在详情浏览期间 MUST 保持不变。更细的分组 MUST 在中间内容区以分区、筛选标签或卡片呈现。

#### Scenario: 切换分类

- **WHEN** 用户在左侧点击「主题」Tab
- **THEN** 二级菜单替换为主题总览与 16 个色系，且自动打开「主题总览」

#### Scenario: 浏览状态保持

- **WHEN** 用户在组件分类下打开某组件详情后返回集合页
- **THEN** 当前 Tab、子菜单选中项与左侧滚动位置保持之前状态

### Requirement: 右侧双态看板

右侧看板 SHALL 具有两种状态：默认展示当前页面目录与页面/分类元信息；用户在中间内容区点击可检查对象（卡片、Token 行、色板等）后，看板 MUST 原位切换为该对象的属性与说明（含可用的复制操作）；关闭或清除选中后 MUST 恢复默认目录态。没有独立详情页的轻量对象 MAY 只提供右侧看板预览，但其卡片 MUST 明确标示该操作结果。

#### Scenario: 点击对象切换看板

- **WHEN** 用户在样式页点击一个 Token 行
- **THEN** 右侧看板从目录态切换为该 Token 的属性看板（名称、值、类型、复制操作），页面布局不跳动

#### Scenario: 关闭恢复目录

- **WHEN** 用户关闭属性看板
- **THEN** 右侧恢复展示页面目录与元信息

### Requirement: 底部构建信息栏

资产库页面底部 SHALL 固定展示当前构建版本、最近同步时间与 Git 提交号，三者均 MUST 来自构建期注入的真实值。

#### Scenario: 查看构建信息

- **WHEN** 用户查看任一资产库页面底部
- **THEN** 可见构建版本、最近同步时间与 Git 提交号，且与当前构建一致
